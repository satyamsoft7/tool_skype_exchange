Security, Privacy & Architecture Specification

Document Version: 2.4 • Last Updated: October 2026 • Model: Client-Side RAM Ingestion (Zero-Transit) • Inquiries & Support:
Executive Summary for Security & Compliance Officers: CloudTrim operates on a zero-server, client-side data minimization model. Unlike legacy SaaS FinOps platforms, CloudTrim requires zero cloud API keys, zero Entra ID app registrations, and zero database storage. All tenant data ingestion and calculations execute strictly within the administrator's local browser memory (RAM) via standard HTML5 File APIs.

1. Architecture & Data Boundary

Traditional cloud management tools require global tenant permissions (e.g., Application Administrator, Directory.ReadWrite.All) and persist corporate user directories in third-party multi-tenant databases. CloudTrim eliminates third-party transit risk by maintaining a strict air-gap between your tenant credentials and any external network.

Data Flow & Isolation Model:
Step 1: Local Discovery
PowerShell on Workstation
Admin runs local export script. Connects directly to Microsoft Graph and Azure APIs using admin's own credentials. Generates local CSV snapshots on the admin's machine.
Step 2: Browser Ingestion
In-Memory HTML5 File API
Admin drops CSV into browser. Browser reads file bytes directly into client RAM using JavaScript FileReader. 0 network calls sent to any server.
Step 3: Local Remediation
Tailored Script Execution
Browser generates preflight-checked PowerShell scripts. Admin reviews and executes scripts locally via PowerShell terminal with -WhatIf dry-run safety.

2. Evidenced Security Controls & Commitments

Rather than relying on generic, self-asserted marketing badges, CloudTrim provides specific, verifiable technical commitments:

Control Area CloudTrim Technical Implementation Verification / Evidence
Credential Security Zero ingestion of Entra ID client secrets, passwords, OAuth refresh tokens, or certificates. Admin authenticates via official Microsoft modules (Connect-MgGraph, Connect-AzAccount) on their own endpoint.
Data Transit (Network Ingress) No directory data, user identities (UPNs), or cloud resource names ever leave the browser session. Verifiable in browser DevTools Network tab: zero POST/PUT requests containing customer tenant payload.
Data at Rest & Retention Zero server-side database storage. Data exists in browser heap memory and is purged upon tab close or refresh. No backend relational or NoSQL database is provisioned. Code runs as static client-side JavaScript.
Script Safety & Production Readiness Remediation scripts use exact Microsoft SkuId GUIDs, enforce -WhatIf dry-run safety by default, verify AccountEnabled -eq $false, check Azure resource locks, and log execution via Start-Transcript. Inspectable script code block generated directly in the UI prior to copying or execution.
Local Task Automation Scheduled audits run via Windows Task Scheduler on the customer's workstation. Historical CSVs reside in C:\CloudTrim\History\. PowerShell script source code is fully transparent, open for internal security review, and uncompiled.

3. Regulatory & Compliance Standard Alignment

3.1 GDPR (General Data Protection Regulation) Alignment

  • Data Minimization (Article 5(1)(c)): CloudTrim does not collect, process, or aggregate personal data on central servers. Directory parsing is confined to client memory on the data controller's device.
  • Cross-Border Transfer Restrictions (Chapter V): Because data never leaves the administrator's local machine, no international data transfers or standard contractual clauses (SCCs) are triggered.
  • Right to Erasure (Article 17): Closing the browser tab or clicking "Clear Session" instantly zeroes all memory structures containing parsed records.

3.2 Zero-Server Data Minimization & Perimeter Boundary Isolation

  • Local Ingestion Boundary: No service accounts, app registrations, or privileged tenant roles are granted to CloudTrim. Access remains entirely governed by your organization's native Conditional Access, MFA, and Entra ID PIM policies on the administrator's workstation.
  • Elimination of Third-Party SaaS Exposure: Because all directory processing is confined to local browser RAM, your tenant data is never exposed to third-party multi-tenant databases or external breach perimeters.

3.3 Digital Personal Data Protection (DPDP) Act, 2023 Alignment

  • Data Fiduciary Identification: CloudTrim is operated by Satya Pathak (SkypeExchange4U), New Delhi, India.
  • Purpose Limitation & Local Processing: CSV files uploaded by the user are parsed exclusively in temporary browser heap memory to compute licensing metrics. No personal identifiers (names, emails, UPNs) are transmitted or persisted externally.
  • Statutory Grievance Redressal: Inquiries or statutory notices under the DPDP Act 2023 may be directed to our designated Grievance & Support channel (acknowledged within 48 hours and resolved within 30 days).

3.4 PCI-DSS Non-Applicability

CloudTrim Community Edition is 100% free for in-browser use. Online credit card and payment processing are disabled. CloudTrim does not process, store, or transmit cardholder or payment data.

4. Vendor Assessment Questionnaire FAQ

Common questions from Enterprise InfoSec & Procurement teams:

Q: Does CloudTrim require an Azure Enterprise Application registration?

No. CloudTrim does not require an Enterprise Application, multi-tenant app consent, or client secrets in your Entra ID tenant.

Q: Can CloudTrim inadvertently modify live production services?

No. Generated remediation scripts explicitly include the -WhatIf dry-run safety parameter by default and require manual review and execution by an authorized administrator in an elevated PowerShell session.

Q: Where are audit reports and history files saved?

All CSV files, execution logs, and PDF exports are saved to your local filesystem (e.g., C:\CloudTrim\History\ or your local Downloads directory).
